# sc-quantum – Quantum range and flight time analysis (Star Citizen 4.10.2-LIVE)

Working directory for a ranking of ships by quantum range, grouped by quantum drive size, plus a flight time
simulation. All data comes from the Star Citizen Wiki API and is stored locally so the API does not have to be
queried again.

> **Note:** This project was generated 100% by AI (GitHub Copilot CLI). Results have not been independently
> verified; see [Known limitations](#known-limitations).
>
> The data comes from [Star Citizen](https://robertsspaceindustries.com/) (Cloud Imperium Games) and from
> community sites: the [Star Citizen Wiki](https://star-citizen.wiki/) (via its
> [API](https://api.star-citizen.wiki/)) and [UEX Corp](https://uexcorp.space) (prices). Star Citizen is a
> trademark of Cloud Imperium Games; this is an unofficial fan project.

## Data sources

- Ships: <https://api.star-citizen.wiki/api/v2/vehicles> (30 per page, parameter `page[number]`)
- Quantum drives: <https://api.star-citizen.wiki/api/v2/items?filter[type]=QuantumDrive&page[size]=100>
  (detail page per item via the `link` field)
- Version: <https://api.star-citizen.wiki/api/v2/game-versions> (currently 4.10.2-LIVE.12881860, 2026-10-09)
- Prices: field `uex_prices.purchase` of the API (data from UEX, <https://uexcorp.space>), community data.

The API requires a browser User-Agent (otherwise HTTP 403 on `/api/items/...`).
The data is not updated automatically. After a new patch run:

```
cd sc-quantum
python3 update_data.py             # fetch from the API and rebuild everything
python3 update_data.py --no-fetch  # only rebuild the derived files from the local data
```

`update_data.py` downloads all ship pages and quantum drives into a temporary directory and replaces `ships/`,
`drives/` and `version.json` only if every request succeeded (failed requests are retried). Drives that are equipped
on ships but missing from the item list are fetched via the ship ports. Then it updates the version in `README.md` (from `version.json`) and rebuilds `combos.json`,
`ranking.md`, `flighttime.json` and `web/data.js`. It needs only the Python standard library.

## Calculations

### Quantum range

```
range (Gm) = tank (SCU) / fuel_consumption_scu_per_gm
```

- Tank: `quantum.quantum_fuel_capacity` of the ship (stock loadout).
- `fuel_consumption_scu_per_gm`: field of the drive (`quantum_drive.fuel_consumption_scu_per_gm`).
- The formula reproduces the minimum of the SPViewer span (checked with Cutlass Black, Cutter Rambler,
  Starlancer MAX). The SPViewer maximum (about 20–25 % higher) is unexplained and not used.
- The field is rounded to 3 decimals in the API. For size 1 (0.004/0.005) the error is large.
  For the Taurus the value therefore differs from SPViewer (385 instead of 350 Gm).
- The ship field `quantum.quantum_range` used earlier (based on `quantum_fuel_requirement`) does not match
  SPViewer and is not used.

### Combinations

- Only ships with a stock quantum drive, a tank size and at least one aUEC purchase price (130 ships).
  Ships that cannot be bought (for example Wikelo specials, Idris, Javelin) are excluded.
- The drive size is taken from the stock loadout. Only drives of this size are combined.
- Excluded: placeholder drive and Mauler drive.
- If several records share a name, the lowest purchase price over all records is used.

### Flight time simulation (`flighttime.py`)

Route:

1. Undock, 5 km in SCM (from standstill, no braking)
2. 10 km in NAV to the quantum point (from SCM speed to max, no braking)
3. Quantum jump 60 Gm, target 30 km away
4. Gain distance (10 km NAV from standstill), quantum jump 3 Gm, target 30 km away
5. Gain distance (10 km NAV from standstill), quantum jump 30 Gm, target 30 km away

Assumptions:

- Acceleration SCM = `scm / zero_to_scm`, NAV = `max / zero_to_max`, braking = `max / max_to_zero`.
  These are the API fields `speed.*`. Constant acceleration.
- NAV mode is assumed to run at `speed.max`.
- QT: stage 1 up to `engage_speed` with `stage_one_accel_rate`, stage 2 up to `drive_speed` with
  `stage_two_accel_rate`. Braking is assumed to mirror acceleration (the API gives no values).
  If the distance is too short for top speed, the peak speed is calculated.
- The drive spool time (`spool_up_time`) counts in full before each jump.
  In game it can partly overlap with the approach, so the result is rather conservative.
- Drive cooldown: only the waiting time left after approach and distance gaining is counted.
- The 10 km for "gain distance" is an assumption, no value was specified (`GAIN_M`).
- Not considered: alignment, calibration, boost, mass and load effects, collisions, in-game waiting times.
- The total is a model calculation, not a time measured in game.

Constants (`UNDOCK_SCM_M`, `NAV_TO_QT_M`, `QT1_M`, `QT_SHORT_M`, `QT2_M`, `ARRIVAL_M`, `GAIN_M`) are at the top of
`flighttime.py`.

Usage:

```
cd sc-quantum
python3 flighttime.py        # comparison list sorted by total time, writes flighttime.json
```

The comparison combinations are in `COMBOS` (Corsair, C2, 315p, Cutlass Black, C1 Spirit, Constellation variants).

## Browser table (`web/index.html`)

Rebuild after data changes:

```
cd sc-quantum
python3 build_web.py
```

Then open `web/index.html` in a browser (a reload is enough).

Features:

- Sticky header, virtual rendering (Tabulator), so large tables stay responsive.
- Sort by clicking the column headers; clicking again toggles the direction.
  **Shift+click** adds further columns as the next sort keys.
- Dark theme by default, with a light theme toggle (stored in the browser).
- Frozen Ship column, column groups, grade badges, range bars and a green-to-red color scale for the flight times.
- Show/hide columns via the *Columns* menu (stored in the browser).
- Filters: search (ship/drive), QD size, grade, minimum cargo, maximum price in million aUEC, stock drive only,
  with price only, complete rows only (hides rows with an empty value in any visible column, so hiding a column
  such as the flight times changes the result). The price limit uses the total price (ship + drive); for a stock drive the ship price.
- Empty values are always sorted last.

Columns (in this order):

| Columns | Content |
|---|---|
| Ship, QD size, Quantum drive, Grade | The combination; Grade is the letter plus drive class (Civ, Ind, Mil, Sta, Com), e.g. `A - Mil` |
| SCU/Gm, Range Gm | Range calculation |
| Speed Mm/s, Cooldown s, Spool s | Drive values |
| Cargo SCU, SCM m/s | Ship values |
| Ship aUEC, Drive aUEC, Total aUEC | Lowest UEX purchase prices |
| **Flight total s** | Total time of the route above |
| **QT 60 Gm s**, **QT 3 Gm s**, **QT 30 Gm s** | Pure quantum flight time per jump |
| **Spool+wait s** | 3 × spool plus cooldown wait |
| **Short-range s** | SCM, NAV, 3 × approach and 2 × gaining distance |
| Tank SCU, Mass t, Stock | Quantum fuel tank, ship mass including loadout, ✓ = the drive is the ship's stock drive |

The flight time columns are calculated for all combinations. For ships without complete flight data in the API
(Aopoa Khartu-al, Aopoa San'tok.yāi, Drake Herald, Esperia Prowler Utility) they are empty.

## Known limitations

- Community data (wiki API, UEX), not official. Prices and values change with patches.
- No comparison with Erkul or SPViewer except for the four reference ships. The SPViewer range maximum is unexplained.
  The SPViewer API (`data.spviewer.eu/spvapi`) requires a token and is not used.
- According to the API the Avenger Stalker has 0 SCU cargo (only 0.71 SCU vehicle inventory); not verified.
- Ship size (QD size) comes from the stock loadout. Whether a ship can take other sizes is not checked.
